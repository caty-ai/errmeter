# errmeter design brief v0 (2026-09-05)

Captured from the owner conversation that started the project. This is the input
to the requirements/architecture lane (contract-freeze issue), not the contract itself.

## Problem

Family agents (Claude Code / Codex / OpenClaw / Hermes, on several hosts) fail often.
Today detection is pull-based (a watchdog goes looking). When the watchers themselves
are down, nobody sees anything and nobody knows where things stopped.

## Goal

Every error from every agent lands somewhere durable with its content, so that
repair agents (nora / doc in our family) get notified and fix it automatically,
and a human is told when nobody is alive to fix it.

## Owner constraints (fixed)

1. As simple and straight as `sitter`. Generic from day one (other families can use it).
2. **No GitHub Actions / paid CI dependency.** Our Actions bill is already above 1200 USD/month.
   Monitoring, notification and dispatch run on our own machines (VPS or any always-on box).
3. Node.js, floor **Node 18** (Claude Code's own minimum). Zero external dependencies,
   no TypeScript build, no language/runtime features newer than 18. Verified on 18/20/22/24 without Actions.
4. Cross-platform: macOS / Linux / Windows. Do not depend on cron. The watcher loops itself,
   and only "start at boot" is OS-specific (launchd / systemd / Task Scheduler), generated by `errmeter install`.
5. Tool repo and inbox repo are separate. Tool: caty-ai/errmeter (private, public after the
   publication gate). Inbox: private per family (ours: shojikumaru/errmeter-inbox).

## Four layers (responsibility split)

| layer | runs where | knows about |
|---|---|---|
| emit | each agent, one command | only a local spool file. Never fails, never needs network |
| spool | local append-only file, one JSON per line, sent/unsent mark | the emit schema only |
| sink | replaceable adapter: `github-issue` (REST via fetch, no `gh` needed), `file`, `webhook` (Telegram/Slack) | spool plus one destination |
| watch | any always-on machine, may run on every family machine | sink location; claims via assignee (first alive wins); dispatches repair; heartbeat gap check |

Rules of thumb:

- git/GitHub is a bulletin board only, read and written via the free API. It never runs anything and is never billed.
- Infrastructure (VPS or any host) is the side that looks, wakes, fixes, notifies.
- Agents are the side that shouts, locally, without knowing who listens.
- Heartbeats go through the same emit (`--kind heartbeat`). No separate mechanism.
- Fingerprint (agent + first error line) dedups storms into comments on one open Issue.
- Logs are redacted (token-like strings masked, tail-N lines only) before leaving the machine.
- CodeRabbit is not a runner. It may review auto-fix PRs, nothing more.

## Open decisions for the contract lane

- Exact emit JSON schema (fields, versioning). Freeze first; everything else depends on it.
- Spool file location per OS and rotation.
- Sink config format (env vs file) and how multiple sinks run together.
- Claim protocol details (assignee vs label vs comment) and staleness of a claim.
- Dispatch hook contract (what `watch` runs when it claims an Issue).
- Auto-fix boundary: PR only vs merge. Owner leaning: PR only, human before merge.
